## Exact versioned native-overlay contract

**Request** (only from future authenticated one-use Controls relay, not an independent Matrix actuator):
```json
{"HBNF":{"overlay":{"id":"hbnf-0123456789abcdef0123456789abcdef","kind":"scoreboard","label":"GLOW","entries":["A -2","B -1"],"ttlMs":12000}}}
```
Bounds: unique ID `hbnf-` + 32 lowercase hex, TTL 250–30,000ms, 1–12 nonempty lines at most 63 chars. No `on`, `ps`, `seg`, `fx`, `bri`, presets, Vibe, scene, palette, Motion, Energy/Variation, audioResponse, matrixBrightness, auxBrightness, AudioReactive, DDP or AUX writes. No cloud `overlay:null` or blind retry. The firmware rejects malformed input rather than erasing an active overlay **only after this firmware patch is actually built and installed**.

**Priority:** Future patched firmware refuses any incoming `kind=scoreboard` while an existing `kind=text` overlay is visible, even if the cloud check raced an Owner direct local text. A new direct Owner text can replace Glow, with its own ID/TTL. Same-ID scoreboard replay does not extend original TTL, but Controls must still enforce consumed nonce/revision/fence; different IDs are separately gated. A failed/blocked scoreboard must never be reported as device success from HTTP status alone. On old installed R6, priority is **not firmware enforced**; Controls must fail closed unless an equivalent trusted single-writer arrangement is actually demonstrated. This patch conservatively treats ANY text as higher than scoreboard, and does not authenticate text origin. Trusted Owner explicit `overlay:null` remains supported; cloud must never send blind null.

**ACK and recovery:** Controls must bind challenge/confirmed nonce to one unique intended overlay ID, current owner revision/fence, fresh Matrix release MAC/preset/FX/native segment baseline and authenticated AUX readback.
