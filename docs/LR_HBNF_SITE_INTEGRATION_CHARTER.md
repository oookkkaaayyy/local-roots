**Mandatory design-review rubric, applied to LR AND HBNF:**
- **Brand system:** establish their relationship, independent recognition, authentic original marks/lockups, consistent but differentiated tone, navigation and visual rhythm.
- **Typography:** test real type families and pairings, accessible sizes and line lengths, optical sizes/weight/letterspacing/leading, numerals/tables, hierarchy and font-loading/performance; never inherit Georgia/Inter automatically.
- **Composition:** intentional responsive grid, proportion, alignment, negative space, page rhythm, density, imagery and content hierarchy; prioritize meaningful tasks rather than generic oversized hero blocks or empty display cards.
- **Refined details:** justified borders, dividers, radii, iconography, material/texture restraint, hover/focus/active/disabled/empty/loading/error states, deliberate micro-interactions, readable transitions and reduced-motion behavior. These micro-details must enhance comprehension and perceived quality, never clutter or create layout shifts.
- **Color:** use the accepted Bone Ink palette only as the first exploration, then test *actual* foreground/background/component states against WCAG AA; shared hues must serve semantic meaning and visual cohesion, not act as decorative patches.
- **Product UX:** show representative actual content and complete user journeys across LR Events, LR HBNF discovery, D&U entry and HBNF-to-existing-scoring handoff; demonstrate iPhone and desktop behaviors, taps, focus, reflow and navigation. Do not alter HBNF score math/tag transaction UX outside separate approved scope.
- **Quality gate:** designer/coordinator reviews FULL-RES actual visually rendered representative screens and compares to both live baselines, rejects generic/underdeveloped comps, cites specific design reasons and iterates. Browser screenshot or high-fidelity preview alone is not owner acceptance. No presentation to owner until the reviewer would defend typography, spacing, hierarchy, aesthetics, platform fidelity and actual task clarity.

**Process correction:** Do not automatically spin up three unrelated concepts or treat the old palette card as the seed layout. First construct a succinct, evidence-backed cross-brand design strategy and decide on a cohesive design system with meaningful variants; then deliver **one genuinely polished, cohesive design direction for both brands**, with only targeted alternatives for material disputed decisions. Iterate intentionally through expert critique and owner visual feedback. Preserve the strict one-sequential-Codex-worker/low-Mac-usage ceiling. No implementation, merge, release or production mutation without separate scoped owner approval.

## 2. Permanent reference framework

- **UX:** Nielsen Norman Group 10 usability heuristics (https://www.nngroup.com/articles/ten-usability-heuristics/); test real primary tasks and recovery paths; mobile-first touch, clear feedback, consistency, low recognition load and restrained complexity.
- **Accessibility:** W3C WCAG 2.2 (https://www.w3.org/TR/WCAG22/), target AA for public and authenticated interfaces; verify actual contrast, focus/keyboard flow, accessible names, reflow, touch target size, error messaging and status semantics. WCAG is a testable criterion set; accessibility is not guaranteed by a palette score.
- **Visual/color:** W3C CSS Color Level 4 (https://www.w3.org/TR/css-color/), including perceptual OKLCH where helpful for systematic hue/chroma/lightness adjustments. Validate contrast using WCAG criteria; visual hierarchy, content density, brand differentiation and harmony require context-specific expert review rather than arbitrary formulas.
- **Performance:** web.dev Core Web Vitals (https://web.dev/articles/vitals); good p75 targets LCP <= 2.5s, INP <= 200ms, CLS <= 0.1; measure mobile and desktop separately and use real-user metrics if available.
- **Security:** OWASP ASVS v5.0.0 (https://owasp.org/projects/asvs) as risk-relevant verification guidance; review authZ, exposed surfaces, injection, sessions, data minimization and privacy. Do not require irrelevant controls or treat a checklist as proof.
- **Data/platform:** Supabase RLS (https://supabase.com/docs/guides/database/postgres/row-level-security) and migrations (https://supabase.com/docs/guides/deployment/database-migrations); existing Local Roots least-privilege RPC and separated HBNF operational backend remain the default boundaries.
- **Deployment:** Cloudflare Pages preview deployments (https://developers.cloudflare.com/pages/configuration/preview-deployments/); Cloudflare Workers versions/gradual rollout/rollback (https://developers.cloudflare.com/workers/versions-and-deployments/); deployment version rollback does **not** roll back external database changes.
- **AI coordination:** Official OpenAI prompting guidance (https://developers.openai.com/api/docs/guides/prompt-engineering): precise bounded instructions, explicit desired output/test/stop conditions, examples when they disambiguate, and evaluation from independent evidence. Avoid recursive meta-prompting and unnecessary delegation.
- **Renewal rule:** Check source currency/applicability at consequential decisions or when platform behavior has changed; do not repeatedly research unchanged stable standards as ceremony.

**Resource ceiling:** At most **one Codex worker** for this project, with **no parallel subagents/workers and no overlapping Codex sessions** initiated by this project. **Stage 1 — Technical read-only integration audit:** same single worker (only if needed) examines exact route/auth/DB/deployment/source map; existing LR/HBNF integration; boundary matrix (read, write, identity, caching, offline); minimal viable options; risks, regression gates and rollback. Produce **one high-quality integrated direction** with focused meaningful alternatives when warranted, not three disconnected generic options. Internally review actual rendered screens and iterate before sharing. Reference Bone Ink PDF for colors only. Preserve working HBNF scoring UX unless directly authorized.

**Stage 3 — Owner review:** stop Codex activity; coordinator presents the specific findings, recommended architecture and visual options, then obtains consequential owner decisions/visual acceptance. No inference from silence.

**Stage 4 — Approved implementation and tests:** resume the **same sole worker** only for bounded approved changes. Reuse validated evidence, test only changed contracts and necessary regression gates, preserve the exact baseline and recovery path, and require separate production authorization.

Use a minimal sequential handoff (one short checkpoint/source ref and next task), not multiple coordination documents. A task must have clear scope, exclusions, deliverable, acceptance criteria and stop conditions. Do not optimize for parallel completion at the expense of total cost, usage or machine responsiveness.
